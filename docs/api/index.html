API reference

The public functions and classes of the chinese_postman package. For the methods behind them, see the 2026 report.

chinese_postman.bnb

Branch-and-bound for the pairing step: the 1997 method, the tightened bound of section 8.3 of the 2026 report, and an improved variant. The CPP itself uses Edmonds' blossom algorithm (cpp.py); this module exists to measure the search that the 2026 version replaced.

Outcome of a branch-and-bound run; costs and pairs refer to the matrix given.

The 1997 bound; returns None for a node whose free vertices cannot all be paired by the parity test of the 1997 routine `cota` (an odd number of empty rows).

Cheapest pair first, then swaps between two pairs until none improves.

Minimum-cost perfect pairing of the t×t symmetric integer matrix D.

chinese_postman.mixed

Mixed Chinese Postman Problem: two-way streets (edges) and one-way streets (arcs).

class MixedGraph

A street network whose links may be one-way or two-way.

MixedGraph.nodes(self)

All vertices, sorted.

MixedGraph.counts(self)

Return (vertices, two-way links, one-way links).

MixedGraph.digraph(self)

Every allowed direction of travel, keeping the cheapest parallel link.

MixedGraph.is_feasible(self)

Return True if a tour exists: the network is strongly connected.

class MixedSolution

A mixed tour with its cost, lower bound and whether it is proven optimal.

MixedSolution.gap_to_bound_pct(self)

Percentage by which the tour exceeds the lower bound, or None without a bound.

lower_bound(M: MixedGraph)

Solve the linear relaxation; return (value, columns, solution).

solve_exact(M: MixedGraph, time_limit: float=300.0, start=None)

Solve the integer program with HiGHS, with zero relative gap, within `time_limit`.

bounds(M: MixedGraph)

Two valid lower bounds: the LP relaxation (ignores parity) and the undirected CPP of the underlying graph (ignores directions). Returns (best, lp, undirected, lp_data, cpp_solution).

solve_heuristic(M: MixedGraph, start=None, pre=None, local_seconds: float=60.0)

Four starting orientations — LP rounding (two tie rules) and the Euler-circuit orientation of the parity-fixed underlying graph (both directions) — each completed by an exact min-cost rebalance; the two best are improved by dual-guided flips (local search).

solve_mixed(M: MixedGraph, time_limit: float=300.0, gap_tol: float=0.0, start=None)

Combined strategy: heuristic first, exact branch-and-cut only while it can still pay off. 1. Bounds + heuristic (seconds): a good tour and a certified gap. 2. If that gap is already within `gap_tol`, stop. 3. Otherwise run branch-and-cut for the remaining time, told to look only for tours cheaper than the heuristic (an objective cutoff) and to stop at `gap_tol`. If no cheaper tour exists the model is infeasible, which proves the heuristic tour optimal. The result always carries the best tour found and the best proven lower bound. gap_tol = 0 (default): prove the optimum unless the time limit runs out. gap_tol = 0.005: accept any tour certified within 0.5% of the optimum (much faster on large networks).

solve_brute_force(M: MixedGraph)

Exact optimum by enumerating the direction of every two-way link (tiny cases only).

read_mcpp(path: str)

Read a mixed instance in the format of Corberan et al. (the MA and MB sets): `(i, j) coste c_ij c_ji`, where 99999999 forbids that direction.

from_graph(G: nx.MultiGraph, oneway_frac: float, seed: int=0)

Make a fraction of the links one-way (random direction), keeping strong connectivity: any one-way link that breaks it is turned back into a two-way street.

city_grid(rows: int, cols: int, oneway_street_frac: float=0.6, block: int=80, avenue: int=270, seed: int=0)

Grid town where whole streets are one-way (as in most city centres): each row or column street is one-way with the given probability, in a random direction.

chinese_postman.rural

Rural Postman Problem: serve only some streets, travel along any.

class RuralSolution

A rural postman tour with its costs, lower bound and proof status.

RuralSolution.gap_pct(self)

Percentage by which the tour exceeds the lower bound.

class Problem

Shortest paths between the required vertices and the pieces of the required streets.

Problem.path(self, i, j)

Shortest path between required vertices i and j (indices into V) as graph nodes.

Problem.deadhead_edges(self)

Edges of the reduced graph: pairs of required vertices whose shortest path does not pass through a third required vertex (the others are never needed).

heuristic(P: Problem, local_seconds: float=10.0)

Frederickson's method plus a local search on the links that join the pieces. Returns (deadhead links, cost of deadheading, info).

lower_bound(P: Problem, rounds: int=30, seconds: float=20.0)

Best of two bounds on the cost of any tour: * parity: every odd vertex of the required streets must be paired, so the deadheading costs at least a minimum matching of them (the CPP argument of chapter 3); * connectivity: the linear relaxation of the model, with the cut around every piece and further cuts x(delta(S)) >= 2 found by minimum cuts of the fractional solution.

solve_exact(P: Problem, time_limit: float=60.0, cutoff: float | None=None)

Branch-and-cut: HiGHS solves the integer program; whenever its solution is disconnected, the cut around each component is added and the program solved again. Returns (status, deadhead links or None, best lower bound on deadheading, rounds).

solve_rural(G: nx.MultiGraph, depot=None, time_limit: float=60.0, local_seconds: float=10.0)

Serve every required street at least cost. One piece of required streets: exact, polynomial (matching), always. Several pieces: Frederickson's heuristic, a local search on the resulting route, then branch-and-cut told to beat it within `time_limit`. The result carries the best tour found and the best proven lower bound.

solve_brute_force(G: nx.MultiGraph, depot=None)

Optimum by enumerating multiplicities 0..2 of every reduced edge (tiny graphs only).

solve_two_costs(G, start=None)

Every street required, first pass at `service`, later passes at `weight`: exact and polynomial, undirected (matching) or directed (min-cost flow).

chinese_postman.sequence

Routes as sequences of served streets, joined by shortest paths.

route_cost(P, seq)

Cost of a route: its service plus the shortest paths that join its streets to the depot.

orient(P, seq)

Best direction for every street, keeping the order (dynamic programme, linear time).

insertion(P, seq, e)

Cheapest place and direction to add street e; returns (extra cost, new sequence).

improve(P, seq, seconds=5.0)

Local search on one route: move a street elsewhere (drop and re-add), and reverse a stretch of the route (2-opt), while the route gets shorter.

from_circuit(P, circuit, demand=None)

Order in which a closed walk serves the required streets (the first pass serves).

expand(P, seq)

Vertex sequence of a route through the original network, depot to depot.

overpass_query(south, west, north, east)

Return the Overpass API query for the streets inside a bounding box.

from_osm(data, name: str='OpenStreetMap area', max_nodes: int=1500)

Street network from an Overpass API JSON answer. Ways become links between junctions (OSM nodes shared by several ways, or way ends); intermediate points only add length. oneway=yes/1/-1 make one-way links. Only the largest strongly connected part is kept, so that a postman tour exists.

solve_json(inst_json: str, time_limit: float=20.0, gap_tol: float=0.0)

JSON-string wrapper of `solve`, for the in-browser proof.
